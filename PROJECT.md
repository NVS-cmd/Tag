# Проект: CRM сети точек — памятка для разработки

Полное ТЗ: https://claude.ai/code/artifact/db8c8247-d663-4d4a-9186-bbee044c6579
Макет экранов: https://claude.ai/artifact/MHGGsWBLPN9r2xTAWVrF4r

## Роли
- **Суперадмин** — точки, учётные записи, справочники (Django admin, `/admin/`).
- **Управляющий** — все точки: ставки, сотрудники, администраторы, отчёты, журнал, устройства, кнопка «Отключить все».
- **Администратор** — своя точка: смена, сеансы, продажи, расходы, выплаты, закрытие. Видит только свою точку.
- **Сотрудник** (мастер / диспетчер) — запись в базе, входа нет.

## Денежные правила (код: `backend/core/calc.py`, тесты: `core/tests/test_calc.py`)
1. Деньги — целые копейки. Доли округляются до копейки, заведению — остаток, сумма долей = сумме сеанса.
2. Сеанс без диспетчера: мастер × ставка, админ × «% с сеансов».
3. С диспетчером: диспетчер × его ставка; мастер × «ставка при диспетчере» от полной суммы или от остатка (настройка в карточке мастера); админ × «% при диспетчере».
4. Сауна — комната типа «сауна»: без мастера, админ × «% с сауны».
5. Продажа: админ × % по категории товара (бар, кальян, напитки).
6. Ставки копируются в сеанс при записи — изменение ставок не трогает прошлое.
7. Администратор ставит мастеру ставку только в диапазоне точки (по умолчанию 30–60%, меняет управляющий в «Точки и ставки»); вне — только управляющий.
8. Касса: начало + нал. сеансы + нал. продажи − нал. расходы − выплаты. Расхождение ≠ 0 → обязателен комментарий, уведомление управляющему.
9. Выплаты каждый день при закрытии; каждому отметка: выплачено / частично / в долг. Долг = начислено − выплачено.
10. На смену можно поставить мастера с другой точки (подмена) — в любой момент смены; один мастер не может быть на двух открытых сменах; снять мастера, у которого есть сеансы, нельзя.

## Правила, закреплённые в базе
- Комната и мастер не заняты дважды: `ExclusionConstraint` (нужен `btree_gist`, ставится в `docker/db-init.sql`).
- Одна открытая смена на точку.
- Ничего не удаляется: отмена с причиной или архив. Журнал только дополняется.
- Удалить сотрудника с долгом нельзя; администратора с открытой сменой нельзя.

## Запуск
- Windows: `powershell -ExecutionPolicy Bypass -File setup.ps1`. Образы — через `mirror.gcr.io` (настраивается в `.env`).

## Где что
- `core/models.py` — данные; `core/services.py` — все операции (права, правила, журнал); `core/middleware.py` — отключение устройств.
- `core/api.py` — JSON API приложения (суммы в копейках, CSRF через заголовок X-CSRFToken).
- `core/api_manager.py` — API кабинета управляющего (`/api/m/...`), отчёты и выгрузка в Excel.
- `core/static/app/` — приложение: чистый JS без сборки и зависимостей. `app.js` — администратор,
  `manager.js` — кабинет управляющего (подгружается при входе управляющего), `app.css`, `sw.js`.
  Доли в приложении — только предпросмотр, итог считает сервер.
- Любое изменение денег — только через `services.py`.

## Этапы
1. ✅ Каркас, модели, расчёты, демо-данные, админка суперадмина.
2. ✅ API + приложение администратора (PWA): вход с устройством, смена, мастера, сеансы, продажи, расходы, отмены, выплаты, касса, мои смены.
3. Офлайн-режим.
4. ✅ Кабинет управляющего: сводка и тревоги, смена точки (добавить мастера), мастера и диспетчеры, администраторы, точки и диапазоны ставок, устройства и «Отключить все», отчёты + Excel, журнал. Уведомления по SMS и 2FA — к запуску (этап 5).
5. Сервер, HTTPS, бэкапы, пилот.
